# 手順を束ねて配る

[アイデア](README.md) — **手順を書いたものを 1 つに束ねて、置いて、落として使う**話。
[教える側へ回す](coach.md)も[AI に操作させる](desktop.md#人の代わりを-ai-にやらせる駆動の当て)も、
**別々の道から同じ部品を要求している** —— どちらも「手順の一式が相手の機械に届く」
ことが前提になっている。

**フォーマットはもう在る。** 1 本 = 1 フォルダ（`docs/video/<名前>/`）で、
中身は既に「入力だけ」に揃っている。作るのは束ね方ではなく、**運び方**。

## 何を配るか

| | |
| --- | --- |
| 構成 `video.md` | 何を見せる 1 本か |
| 台本 `plan.json` | シーンとビート、`do` と `say`、仕込みの指定 |
| 仕込み `make_sample.py` など | 撮影用のダミーを作る / 片付ける |
| 相手の素性 | `winget` の id（`KDE.Krita` / `7zip.7zip`）。**今はドキュメントにしか書いていない** |
| 参考画像（任意） | 台本を撮ったときのショット。教材なら 1 枚ずつ出す |

**生成物は配らない。** ショット・音声・mp4 は相手の機械で作れるか、そもそも要らない
（動画は [Gallery](https://lancard-aikawa.github.io/GhostMoviePlayGallery/)、
手順は実アプリ）。**入力だけ**なら、いま git に入れているものがそのまま束になる。

## 置き場所（新しいサーバを作らない）

1. **git リポジトリのまま。** いま既にそうなっていて、Gallery のカードが素材の
   フォルダへリンクしている。`gmp get <repo>/<パス>` が sparse に引くだけで届く
2. **zip 1 つ。** GitHub Releases でも社内の共有でもよい。git を持っていない相手に渡せる
3. **一覧。** Gallery の `videos.py` と同じ形（1 本 = 1 ブロック）で、
   「どこにあるか」を並べるだけの表。**索引に新しい仕組みは要らない**

**登録の要る場所を作らない。** 配る先が決まる前にレジストリを立てると、
[手順書レンダラを下げたとき](README.md#見立て)と同じ「腐る素材が増えるだけ」になる。

## いちばん危ないところ —— 落としたら走る

**`plan.json` は `app.setup` / `app.start` / `app.teardown` を持っている。**
つまり**手順の束は、相手の機械で走るコマンドを含んでいる**。いまは
「自分で clone したリポジトリ」だから成り立っているだけで、
**落として使う口を開けた瞬間に、これは任意コード実行の配布路になる。**

作るなら、順番はこうでなければいけない。

1. **既定で走らせない。** 落とした直後に見せるのは**中身**で、`setup` / `start` /
   `teardown` を**全文で**出す。人が読んで通すまで動かさない
2. **出所を出す。** どこから取ったか（URL・取得した日）を束の中に残す。署名は重い
3. **`gmp check --dry` を先に通す。** 撮らずに読むだけで分かる欠陥（空のシーン、
   足りないキー、機械依存の絶対パス）はここで出る。**落とした直後に自動で回す**
4. **相手の場所は落とした側で決める。** exe の在り処は機械ごとに違うので、
   束に焼かない（[coach.md の 3 段構え](coach.md#1-相手を見つける--入れさせる)）。
   **「git に入る plan.json に機械依存の値を焼かない」がそのまま効く**

**「見せる」を後回しにすると、落として走る仕組みだけが先に出来上がる。**

## 出すほう（アップロード）

落とす口を開けるなら、**出す口も同じところに要る** —— 束を作った人が置き場所へ
上げるまでが 1 続きでないと、結局「手で zip を作って手で上げる」に戻る。

**ここでも新しいサーバを作らない。** 出し先は落とす先と同じ 3 つ。

| 出し方 | 手段 | 向いている相手 |
| --- | --- | --- |
| git に入れる | いまと同じ。**素材は元からリポジトリにある** | 公開しているプロジェクト |
| zip を上げる | `gh release upload` / 共有に置く | git を持っていない相手、社内 |
| 索引に 1 行 | Gallery の `videos.py` と同じ形 | どこにあるかを並べるだけ |

### 上げる前に止めるもの

**出す口は、漏らす口でもある。** ここは机上の心配ではなく、Krita の 1 本を出す間に
**3 回踏んだ** —— 動画にユーザー名（GlossPop、97 秒間）、サムネにユーザー名、
ドキュメントの画像にユーザー名。**どれも「出す直前」まで気づかなかった。**

`gmp pack` は上げる前に束の中を見て、少なくともこれを止める。

- **ユーザー名を含むパス**（`C:\Users\<名前>\...`）。台本にも仕込みにも参考画像にも入り得る
- **機械依存の絶対パス。** `plan.json` については `tests/test_plan.py` が同じ規則で
  既に見ている —— **検査は在って、束に向けていないだけ**
- **生成物**（`*.mp4` / `*.wav` / `shots/`）。入れない決まりなのに、束ねるときは
  「あるものを全部」入れたくなる
- **実データ。** 撮影用のダミーを作る決まり（`app.setup`）がここにも効く。
  仕込みが**作る**ものは束に要らない —— **束に入っているデータは、誰かの本物**

**止めるのは `gmp pack` であって人ではない。** 3 回とも人が見落としている。

## 他にも効く

束が運べるようになると、いまバラバラに詰まっているものが同じ形で解ける。

- **`gmp check` を別の機械で。** 台本と撮る対象が別リポジトリのとき、いまは
  「両方 clone した人」しか検査できない
- **サンプルを配る。** `examples/demo` は clone しないと試せない
- **教材として渡す**（[coach.md](coach.md)）/ **AI に操作させる**
  （[desktop.md](desktop.md#人の代わりを-ai-にやらせる駆動の当て)）—— 元々の 2 つ
- **手順書として出す。** 束の中身は `render` を通さなくても読める形になっている

## 見立て

**作るのは 4 つだけ。** 束ねる（`gmp pack`）、出す、取ってくる（`gmp get`）、
**走らせる前に見せる**。

**順番は「見せる」から。** 束の中の `setup` / `start` を全文で出して人が通す画面は、
`gmp get` が無くても（いま手元にある `plan.json` に対して）そのまま役に立つし、
**それだけで「落として走る」の危なさが先に潰れる。**

**その次が「上げる前に止める」。** こちらも `gmp pack` を待たずに、いまある
`docs/video/*/` に向ければ今日から効く —— **ユーザー名の漏れは、束ねる仕組みが
無いうちから既に 3 回起きている。**

運ぶところ（`pack` / `get` / 出し先）は最後でいい。**見せると止めるが先に入って
いれば、運ぶのは薄い。**

**索引は Gallery の形をそのまま借りる。** あちらで `videos.py` 1 枚に情報を寄せて
生成する形にしたばかりで、同じ手が使える。
