# 落とした設定で撮る（zip を受け取った側の手引き）

[README](README.md) — [Gallery](https://lancard-aikawa.github.io/GhostMoviePlayGallery/) の
カードから落とせる **設定一式の zip**（`<名前>.zip`）を、自分の機械で回すための手引き。

**この文書は Claude Code に渡す前提で書いてある。** 下の[頼み方](#claude-への頼み方)を
そのまま貼れば、確かめるところから通しで撮るところまで代わりにやってくれる。

## 落としたものは何か

| 入っている | 入っていない |
| --- | --- |
| 構成 `video.md`（何を見せる 1 本か） | 動画 `output.mp4`（Gallery で観るもの） |
| 台本 `plan.json`（シーン・ビート・セリフ・仕込みの指定） | 音声 `voice/*.wav`、ショット `shots/`（**手元で作る**） |
| 仕込み `make_sample.py` など（撮影用のダミーを作る / 片付ける） | 収録対象そのもの（別リポジトリ・別アプリのことがある） |
| 出所書き `BUNDLE.md`（どこの何コミットか、置き場所、使い方） | |

**入力だけ**なので小さい（数 KB〜十数 KB）。**同じ台本から同じ動画が出る**のが
このツールの前提なので、生成物を配る意味が無い。

## 先に読む —— これはあなたの機械で走る

**`plan.json` の `app.setup` / `app.start` / `app.teardown` は、撮る前後に
あなたの機械で走るコマンド。** 束を開いたら、**まずそこを読むこと。**

```powershell
# 何が走るのかだけ先に見る
uv run gmp config <落とした場所>/video.md      # 効いている値と、その由来
```

Gallery に出ているものは「撮影用のダミーを作って、終わったら消す」だけだが、
**確かめるのは受け取った側の仕事**。出所（`BUNDLE.md` のコミット）と中身が
食い違っていたら、そこで止める。

## 置き場所は束によって違う

**`app.cwd` が何を指しているかで変わる。** `BUNDLE.md` の「置き場所」に 1 本ずつ
書いてあるので、そのとおりにする。

| | |
| --- | --- |
| **どこに置いてもよい** | `app.cwd` がそのフォルダ自身で、仕込みが撮影用のデータを作る（支援収録の 2 本がこれ） |
| **元の場所に戻す** | `app.start` がプロジェクト内のパスを指している（紹介動画は `docs/video/intro/` の `site/` を配信する） |
| **収録対象を別に用意する** | `app.cwd` が別リポジトリのルートを指している（GlossPop は向こうを clone してから） |

置いたら、**撮らずに読むだけの検査**を通す。

```powershell
uv run gmp check <置いた場所>/plan.json --dry
```

## 回す

前提ソフト（ffmpeg / Chromium / VOICEVOX）の入れ方は[環境の用意](docs/setup.md)。

```powershell
uv run gmp doctor                                   # 足りないものを言う
uv run gmp build <置いた場所>/plan.json --voice     # 自動収録はこれで通る
```

**支援収録の 1 本（`app.window` が埋まっているもの）は撮るのが人。**
[README_WINAPP.md](README_WINAPP.md) の手順で、`gmp shoot` の画面から
ビートごとに撮ってから `声を作る` → `収録する` → `仕上げる`。

出来たものの置き場所は `uv run gmp where <plan.json>`。**プロジェクトの外**に出るので、
落とした束のフォルダは汚れない。

## Claude への頼み方

対象プロジェクトを開いた Claude Code に、そのまま貼る。

### 落としてから撮るまで

```
GhostMoviePlay の設定一式 (zip) を落としてきた。<パス> にある。
README_BUNDLE.md に従って、これを使えるようにして。

- 先に BUNDLE.md と plan.json の app.setup / app.start / app.teardown を読んで、
  何が走るのかを日本語で教えて。危ないものがあれば止まって
- 置き場所は BUNDLE.md の「置き場所」に従って。収録対象が別に要るなら教えて
- gmp doctor で足りない前提を調べて、入れ方も教えて
- 問題なければ通しで撮って、尺と警告を報告して
```

### 自分のプロジェクト向けに直す

```
落とした台本 <パス>/plan.json を、このプロジェクト向けに作り直して。
シーンの並びと狙いは活かして、収録対象と操作はこのプロジェクトのソースを読んで書き直して。
声と口調はこちらの gmp.toml に従って。
```

**そのまま撮るより作り直すほうが早いことがある。** 束は「こういう演目が撮れる」の
実例でもあるので、**構成 (`video.md`) だけ借りて台本を書き直す**のは正しい使い方。

## つまずいたとき

| 症状 | 理由 |
| --- | --- |
| `app.url が必要です` | 収録対象が指定されていない。束の `video.md` を見て、自分の環境の URL に直す |
| 起動しない / 真っ白 | `app.start` が別の場所を前提にしている。`BUNDLE.md` の「置き場所」を読み直す |
| 声が出ない | VOICEVOX ENGINE が起きていない（[環境の用意](docs/setup.md)） |
| 声が違う | 束は `voice` を台本に焼いている。`plan.json` の `voice.speaker` を直せば `gmp voice` からやり直せる |
| 読みが違う | `gmp kana <plan.json>` で確認して `voice.dict` に足す（**priority を上げないと効かない語がある**） |
| `gmp check` が `--` になる | **正しい。** 支援収録は撮り直せないので検査できない |
| 撮ったのに絵が違う | 相手のアプリの版が違う。**束は撮った時点のアプリに当たっている**ので、`BUNDLE.md` のコミットと日付を見る |

## 出す側になったら

自分で撮った 1 本を配るなら、**素材のフォルダをそのまま束ねればいい**
（生成物は入れない）。置き場所は自分のリポジトリで足りる ——
[Gallery](https://github.com/lancard-aikawa/GhostMoviePlayGallery) は
索引に 1 行足すだけの形になっている。

**出す前に、束の中にユーザー名や機械依存の絶対パスが入っていないかを見ること。**
出す口は漏らす口でもある（Gallery の `build.py` は見つけたら止まる）。
