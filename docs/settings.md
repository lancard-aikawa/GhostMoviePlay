# 設定と置き場所

[README](../README.md) — 何を撮るかと声の既定をプロジェクトで決めるとき、
生成物がどこに出るかを知りたいときに読む。

## 3 層

設定は 3 層ある。**下に行くほど強い。**

| 層 | ファイル | 置くもの |
|---|---|---|
| グローバル（この機械） | `config.toml`（`gmp config --set`） | 出力ルート、VOICEVOX の接続先、フォント、画質、**声と口調の既定** |
| プロジェクト | `<project>/gmp.toml`（**git に入れる**） | 対象URL・起動コマンド、声と口調、読み辞書、題材と本数、seed |
| 動画 | `video.md` のフロントマター | その動画だけの上書き |

```bash
uv run gmp ui                             # 画面 (層を選んで編集)
uv run gmp config --init-project .        # <project>/gmp.toml の雛形を置く
uv run gmp config                         # いま効いている値と、その由来を全部出す
uv run gmp config docs/video/intro/video.md   # その動画まで含めた解決結果
uv run gmp config --set voice.speaker=ずんだもん --set render.crf=18
```

`gmp config` は各項目の値と**どの層から来たか**を並べる。3 層あるので、
これが見えないと必ず迷子になる。`*` が付いている行が「誰かが決めた値」。

**グローバル設定 (`config.toml`) に置けるのは「機械が変われば変わる値」と
「好みの既定」だけ。**
アプリの URL や起動コマンド、`seed` のようなプロジェクト固有の事実は置けず、
書いても警告して無視される（同じ機械で 2 つ目のプロジェクトを撮った瞬間に嘘になる）。
綴りを間違えたキーも黙って消えずに警告が出る。

**読み辞書 (`voice.dict`) はプロジェクトに置く。** 用語の読みは動画をまたいで
共通なので、1本ずつ持つと「1本目で直した読みが2本目で戻る」を必ず踏む。
これだけは層をまたいで**マージ**される（他の項目は上書き）。

`gmp.toml` を作ったあとの `gmp init` は、**共通の値を video.md に書き写さない**
（書き写すと 1本ぶんが常にプロジェクトを上書きしてしまう）。何を継承しているかは
コメントで見えるので、変えたい行だけコメントを外す。

## 画面

ウィンドウは 1 つで、中は **「撮る」と「設定」の 2 面**。上の
`プロジェクト` と `動画` は両方で共有していて、面を切り替えても選び直さない。
`gmp ui` は設定面から、`gmp ui --run` は撮る面から開く。

撮る面は [撮る面](#撮る面) を参照。以下は設定面。

### 編集する層

**まず編集する層を選ぶ。** `このプロジェクト (gmp.toml)` と
`グローバル設定 (config.toml)` は完全に分かれていて、選んだ側だけを編集する。
入力欄には**その層が自分で持っている値だけ**が出る（空欄は「その層では未設定」で、
下に「いま効いている値」が出る）。

こうしてあるのは、行ごとに保存先を選ばせていたころ、グローバル設定から来ている値を
**このプロジェクトだけ変えたつもりで既定（＝全プロジェクト）を書き換えていた**ため。
グローバル設定を編集しているときは、保存先の行が赤くなる。

その中は**用途でタブを切り、行ごとに「値・由来」**を並べる。
`声と口調` / `何を撮るか` / `対象と動画` / `出力とツール` の 4 枚（その層に置けない
タブは出ない。プロジェクトを編集しているときに `出力とツール` は出ない）。

タブの中は区切り（`話者と声` / `原稿` など）でまとまっていて、
**「めったに変えないもの」は畳んである**（見出しをクリックで開く。開閉は
読み直しても保つ）。話速・音高・抑揚・音量のように**常にセットで見る項目は
1 行に並ぶ**。

- **どの層から来た値か**が各行に出る（項目ごとに違うなら項目ごとに）
- その層に置けない項目は**そもそも出ない**（グローバル設定に `app.url` は無い）
- **`! 再合成`** —— その項目を変えると音声を作り直すことを先に言う
- **`! この動画 (video.md) が決めています`** —— そこで上書きされている行。
  上の `動画` で選ぶと印が付く（**編集する場所ではなく、
  「このプロジェクトの設定が効かない項目」を確かめるための欄**。video.md が
  1 つも無いプロジェクトでは出ない）
- **試聴** —— いまの声の設定で 1 文だけ合成して鳴らす。VOICEVOX が起動していなくても
  画面は開き、話者名は手で入力できる

`gmp.toml` は保存先の欄の下で**作る / 削除する**。まだ無いときは、
そこにしか置けない項目（対象URL・起動コマンド・seed など）の入力欄を**出さない**
——埋められないものを埋めようとして詰まるだけなので、代わりに「作ると何行出るか」を
出す。削除は消える中身を並べて確認してから消す。

書き込むのは **`config.toml` と `gmp.toml` だけ**。`video.md` は本文（補足の散文）を
持つので、GUI から書き戻して人の書いた文章を壊さないようにしてある（表示のみ）。
`gmp.toml` への保存は**変更した行だけを当てる**ので、手で書いたコメントは残る。

## 撮る面

選んだ動画について、**いまどこまで出来ているか**と、次に押す段が並ぶ。

| | 見るもの | 「古い」と言うとき |
|---|---|---|
| 構成 | `video.md` | （鎖の先頭） |
| 台本 | `plan.json` | `video.md` のほうが新しい |
| ショット | `shots/` | （見ない。**支援収録のときだけ出る**。下記） |
| 音声 | `voice/*.wav` | （見ない。下記） |
| 収録 | `raw.webm` + `timing.json` | `plan.json` のほうが新しい / **警告が残っている** |
| 完成 | `output.mp4` | `timing.json` のほうが新しい |

**収録は 2 つ作る** —— 無音の映像 (`raw.webm`) と、ビートの実測時刻
(`timing.json`)。行を押すと**撮れた映像**が再生される（字幕も音声もまだ
乗っていない状態が見える）。新しさは `timing.json` で見る。

収録は更新時刻のほかに **`timing.json` の `warnings`** も見る。光らせる相手が
見つからない・選択がずれた・音声が無いは録画を止めないので、件数と先頭の 1 件を
行に出す（**通ったことは、狙った画面が映っている証明にはならない**）。ただし
`仕上げる` は止めない —— 撮れてはいて、直すのは台本のほうだから。CI から回すなら
`gmp record --strict` が同じものを終了コードにする。

**ショットの行は `app.window` を埋めた 1 本にだけ出る**（[支援収録](plan.md#自動操作が届かない相手を撮る支援収録)）。
行をダブルクリックすると**撮る窓が開く** —— ボタンにすると行の複製になるので置いていない。
音声と同じで**揃っているか（何ビートに画があるか）しか見ない**。撮り直しの効かない
ものなので、更新時刻を比べても「アプリが変わったのに画が古い」は分からない。
そのぶん `収録する` は撮らずに**ショットを並べる**（`raw.mp4` が出る）。

音声だけは**揃っているか（何ビートに wav があるか）しか見ない**。新しいかどうかは
`voice/manifest.json` のフィンガープリント（原稿と声のハッシュ）が判定するもので、
更新時刻で比べると嘘になる —— `gmp voice` は manifest を書いたあとに `plan.json` を
書き戻すので、合成した直後でも `plan.json` のほうが必ず新しい。

1 本目は **`構成を作る`** から始める（`gmp init` を呼ぶ）。フォルダ名だけ訊いて、
既に 1 本でもあるなら**その隣**に、無ければ `docs/video/` の下に作る。作ったら
その場で選ぶので、続けて `構成` の行を開いて書いてから `台本を作る` と進める。
video.md が 1 つも無いプロジェクトを選んだときは、段が全部押せないので
「作る」ほうを案内する（**押せない理由は常に下に出る**）。

画面の言葉づかいは [README の「呼び名」](../README.md#呼び名) に揃える。
`台本` の隣に `1本を作る` を置くと、台本の数のことに読める。

**段はボタンの下に「何が出来るか」を出す**（`→ 台本` `→ 音声` `→ 収録` `→ 完成`）。
表の行と同じ言葉にしてあるので、どの段がどれを作るのかが読める。ボタンに
マウスを乗せると詳しい説明が下の帯に出る（`収録する` は字幕も音声もまだ
乗らない / `仕上げる` は撮り直しではない）。

段は `台本を作る` / `声を作る` / `収録する` / `仕上げる` / `通しで作る` の 5 つで、
`gmp plan --open` / `voice` / `record` / `render` / `build --voice` をそのまま呼ぶ
（`--run` ではなく `--open` —— `-p` には訊く相手がいないので、収録対象や
セレクタが決まっていないと claude が何も書かずに終わる）。
**別プロセスで走り、出力は下のログに流れる**（数分かかるので画面は固まらない）。
`中止` は子孫ごと止める（chromium・ffmpeg・claude を抱えているため）。

**開く操作は表の行に集約してある。** 行をダブルクリックすると、その実体を OS の
既定のアプリで開く（`完成` なら再生。tkinter に動画を出す手立ては無い）。まだ
無い行は**出る場所**のフォルダを開くので、どこに出るのかが分かる。

`構成` と `台本` の行は**画面の中のエディタ**が開く。シーンと狙い・本文・タイトルは
構成にしか置けず、設定画面は `video.md` を書かないので、外のエディタに頼ると
画面が自己完結しない。エディタは**構造を触らない** —— 打った文字をそのまま
保存するだけなので、散文もコメントも壊れない。保存前にフロントマターが読めるかを
見て、壊れていたら訊いてから保存する。

`台本` のエディタは**出来た動画を観てから「ここだけ」直す**ための道。ビートを
並べ、選んだビートの静止画（`raw.webm` から抜く）と実測の時刻を出し、
**原稿・字幕・間の 3 つだけ**を直せる。`actions` と selector は入れない
（そのプロジェクトを読まないと決まらないので Claude の領分）。保存すると
**どこからやり直せば反映されるか**を言う —— 字幕だけなら仕上げ直すだけ、
間なら撮り直し、原稿なら声を作り直してから撮り直し。

`雛形から作り直す` は、タイトル・シーン・本文を残したまま枠組みを今の雛形に
揃える。プロジェクトと同じ値になっている上書きは落とす（書き写された共通の値が
残っていると、この動画が常にプロジェクトを上書きし続ける）。相対パスは層ごとに
基準が違うので落とさない。**保存はしない**ので、中身を見てから保存できる。
`構成を編集` / `出力フォルダを開く` / `完成した動画を再生` というボタンを並べて
いたが、行にファイル名が出ている以上あれは表の複製だった。

**外で直して戻ってきたら自動で調べ直す**（ウィンドウがフォーカスを得たとき）。
`調べ直す` ボタンは、それを手で押させていただけなので消した。

画面から渡せるのは **`--headed`（ブラウザを見ながら撮る）だけ**。字幕・音声・
クレジット・画質のような**絵と音を変える指定は画面に出さない**——それらは
`plan.json` と設定で決まるべきもので、とくに `--no-credit` をボタンにすると
VOICEVOX のクレジットをワンクリックで落とせてしまう。要るときは CLI で渡す。

### 収録対象が決まっていないとき

`app.url` が空、または古い `video.md` に見本値（`http://localhost:5173` /
`npm run dev` / `text=スタート`）が残っていると、**構成の行が橙になり理由が段の
下に出て、`収録対象を直す` が現れる**。そのまま Pass1 を呼ぶと AI が「本物の
アプリを指してくれ」と訊いてきて、`-p` には答える人がいないので台本を書かずに
終わるため。押せなくはしない（Vite の既定は本当に 5173 なので当たっていることも
ある）。

`claude に書かせる` は対話の claude を開いて、ソースを読ませたうえで
`video.md` を書かせる（`gmp init --open`）。収録対象もシーン構成も、その
プロジェクトを読まないと決まらないので、**画面が代わりに決める道は持たない**。
書き終えて画面に戻ると自動で調べ直し、橙が消える。

自分で入れたいときは設定面の `対象と動画`（プロジェクトの `gmp.toml` に入る）か、
構成の行を開いて `video.md` に直接書く。

**`app.window`（支援収録で撮る窓）を埋めた 1 本は、`app.url` を要らない。**
ブラウザを開かず、人が操作したその窓を撮るので、収録対象は窓のタイトルのほうで
決まる。埋めると撮る面に `ショット` の行が出る
（[支援収録](plan.md#自動操作が届かない相手を撮る支援収録)）。**自動収録できる
相手には埋めないこと** —— 決定論を捨てるだけになる。

### 収録対象の推測

`gmp config --init-project` と `収録対象を直す` は、プロジェクトを読んで
`app.start` / `app.url` / `app.ready` を埋める。**動かさない**（`npm run dev` を
起こしたりポートを叩いたりしない）。

| | 見るもの |
|---|---|
| 起動コマンド | `package.json` の `scripts.dev/start/serve/preview` と、ロックファイル（`bun.lockb` → `bun run`、`pnpm-lock.yaml` → `pnpm`、…）。`package.json` が無ければ `index.html` を配る簡易サーバ |
| URL | スクリプトの `--port` → `vite.config.*` などの `port` → `.env` の `PORT` → ソースの `Bun.serve` → 依存の既定（vite 5173 / next 3000 …） |
| 準備完了のセレクタ | `index.html` の `<div id="app">` `<div id="root">` の類。無ければ `<h1>` |

**分からないものは書かない**（それらしい既定を焼くと「設定済みに見える嘘」に
戻る）。**なぜその値なのかは必ず添える** —— `gmp.toml` にはコメントで残る。

```toml
[app]
start = 'bun run dev'              # ← bun.lockb と package.json の scripts.dev
url = 'http://localhost:7474/'     # ← src/index.ts の Bun.serve
ready = '#app'                     # ← public/index.html の <div id="app">
# 当たっていなければ書き換える (設定画面の「対象と動画」からでも)
```

推測なので当たらないことがある。`ready` はとくに、**見えた時点で描き終わって
いるとは限らない**ので、収録して足りなければ具体的な要素に差し替える。

### claude は対話で開く

`台本を作る` と `claude に書かせる` は、**対話の claude を新しいコンソールで
開く**（`gmp plan --open` / `gmp init --open`）。`-p`（対話なし）には訊く相手が
いないので、収録対象やセレクタが決まっていないと「本物のアプリを指してくれ」と
訊かれた時点で終わる。開けば人が答えられるし、承認もその場で出せる。

窓を開くとき、**指示はクリップボードにも入る**。claude が自分で始めなかった
ときは `Ctrl+V` → `Enter` で進められる（窓にも同じ 1 行が出る）。長い指示は
依頼文（`PLAN_REQUEST.md` / `SPEC_REQUEST.md`）に置いてあり、窓に出るのは
それを指す 1 行だけ。

画面はその窓の終わりを知らない。**書き終えて画面に戻ると自動で調べ直す**ので、
待つ必要はない。起こしたコマンドは出力フォルダの `gmp-claude.cmd` に残るので、
同じことをやり直せる。

自動で回しきりたいときは `gmp plan --run`（`-p`）。答える人がいない前提なので、
収録対象が決まっているときだけ。

### 台本を作るのが落ちたとき

`台本を作る` は `claude` を `-p`（対話なし）で動かす。このとき**承認の要る操作は
拒否される**ので、claude が台本を書かずに正常終了することがある。

そこで `gmp` は起動前に**出力先へ空の雛形を置く**。`acceptEdits` が自動で通すのは
「編集」なので、新規作成ではなく編集にするため。それでも書かれなかったときは
雛形を消して `gmp: plan.json が雛形のままです` で止まる（中途半端な
`plan.json` は残らない）。画面の `台本を作る` は `--open`（対話）を使うのでこの問題は起きない。`--run`
（`-p`）で回すときの逃げ道は 2 つ。

- `gmp plan <video.md> --open` に切り替える（訊かれたら答えられる）
- **`設定` → `出力とツール` → `Pass1 の claude` → `権限モード`** を
  `bypassPermissions` にする。承認を求めずに走る

失敗の理由（`gmp:` の行とその続き）は段のすぐ下の赤い帯に残る。ログは長い実行の
あとだと上へ流れ、下の帯は次の操作で上書きされるため。

**逃げ道のボタンはこの帯の中にしか出ない**（`前提を調べる` = `gmp doctor`）。
うまくいっている間は押す理由が無いので、常に並べない —— 常時見えるボタンは
`構成を作る` + 段 5 つ + `中止` の 7 つで、失敗したときだけ 1 つ増える。
収録対象が決まっていないときだけ `claude に書かせる` が理由の隣に出る。

## 解決した値の行き先

3 通りある。`gmp config` の見出しがそれ:

| | 行き先 |
|---|---|
| `plan` | plan.json に焼かれる。Pass2/3 が読む |
| `brief` | `PLAN_REQUEST.md` に載るだけ。plan.json には残らない（口調・題材・尺） |
| `runtime` | この機械でだけ効く。plan.json には入らない（接続先・フォント・画質） |

**`plan` の値は Pass1 の時点で plan.json に焼き切る。** `record` / `render` が
設定ファイルを読むと、同じ plan.json が機械ごとに違う動画を出すようになる。
`gmp plan` が書く依頼文には「**そのまま使う値**」として解決済みの JSON が
入っていて、AI はそれを写すだけ。だから **plan.json は設定ファイル無しでも
そのまま撮り直せる**（別のマシンに持って行っても同じ動画になる）。

`app.cwd` のような相対パスは、**それを書いたファイルからの相対**として解釈して
plan.json の位置に直してから渡す。`gmp.toml` の `cwd = '.'` はプロジェクトルート、
`video.md` の `cwd = '.'` は動画のフォルダで、別の場所を指す。

## ファイルの置き場所

**ソースと生成物を完全に分ける。** プロジェクトの git には `gmp.toml` と `video.md` と
`plan.json` しか入らないので、**プロジェクト側に .gitignore が要らない**。

```
プロジェクト（git 管理）
<project>/gmp.toml   プロジェクト共通の既定（対象URL・声・口調・題材・読み辞書）
<project>/docs/video/getting-started/
  ├─ video.md      手で書く指示。gmp.toml を上書きする
  └─ plan.json     AI が書いた台本。手で直す資産。AI コストはここだけ

ユーザフォルダ（git 外）
~/Videos (Win) | ~/Movies (Mac) /GhostMoviePlay/<project>/<video>/
  ├─ PLAN_REQUEST.md
  ├─ voice/*.wav
  ├─ raw.webm / timing.json / subs.ass
  └─ output.mp4
```

`plan.json` はセレクタとアプリの挙動に依存していて**腐る**。だから対象プロジェクトの
git に置き、UI の変更と同じ diff に乗るようにする。ツール側に集めると必ず放置される。

置き場所は上から順に決まる:

1. `--out DIR`
2. 環境変数 `GHOSTMOVIEPLAY_HOME`
3. 設定ファイル（`gmp config --set-home DIR`）
4. プラットフォーム既定

```bash
uv run gmp where                        # 解決結果を見る
uv run gmp config --set-home D:/videos  # 出力ルートを変える
```

**Win/Mac で名前が一致する動画フォルダは存在しない** — Windows は `Videos`、
macOS は `Movies`。Linux は XDG。プラットフォームごとに解決している。
Windows は Known Folder が OneDrive などにリダイレクトされていることがあるため
レジストリを引く。`Documents` を使わないのは、リダイレクト先が OneDrive のことが多く、
数百MB になる `raw.webm` がクラウド同期に乗ってしまうため。
