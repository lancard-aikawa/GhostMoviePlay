# 撮る道具から、教える道具へ（コーチング）

[アイデア](README.md) — **支援収録の画面を、人に付き添う道具として別アプリにする案**。
観せるのではなく、**教わる人が自分の機械で本物のアプリを操作する**のに横から付き添う。

**まだ何も測っていない。** 下は机上で、実装の見積りも「既にある部品」から数えただけ。

## なぜ近いか

[支援収録](../../README_WINAPP.md)の画面は、既に**上から順に `do` を読ませて、人に
本物のアプリを操作させる装置**になっている。撮るかどうかしか違わない。

| | 撮る (`gmp shoot`) | 教える (coach) |
| --- | --- | --- |
| 操作する人 | 台本を書いた側 | **教わる人** |
| `do` | 撮るためにやること | **やること**（そのまま） |
| `say` | 観る人への言葉（動画に乗る） | **その場で読ませる説明** |
| ショット | 成果物（並べて動画になる） | **任意**（やった証跡・質問に添える絵） |
| 画面 | 一覧 + 編集欄で埋まる | **1 ビートを全文で出す**（編集しないので広く取れる） |
| 次へ | 撮ったら次のビートへ | **出来たら次のビートへ** |
| 仕込み・後片付け | `起動` / `終了` | **そのまま**（`app.setup` / `app.teardown`） |

**7-Zip と Krita の 2 本は、既に教材そのもの。** 「一部を選択したまま描くと筆が
反応しない」を、絵ではなく手で踏ませられる。

## 新しく書く部分だけ

撮る部分（`capture.py`・ウィンドウの掴み方・仕込みの順序）は **1 行も新しくない**。

### 1. 相手を見つける / 入れさせる

- **入っていない**: `winget` の id を台本に持たせて出す。ドキュメントには既に
  `winget install KDE.Krita` / `7zip.7zip` と書いてあるので、**書く場所が無いだけ**
- **入っているが場所が違う**: 3 段構えにする。
  1. **起動中のウィンドウから選ぶ** —— `capture.windows()` で既に出来ている（いちばん確実）
  2. ファイル選択で exe を指す
  3. **ショートカット / exe をドロップさせる** —— `.lnk` の解決が要る（`IShellLink`
     か `WScript.Shell`）。**Tk は素で D&D を受けない**（`tkdnd` が要る）ので、
     ここは上乗せの位置に置く。**未検証**
- **確定したパスはその機械に覚える。** 設定の層でいう `machine`。**台本に焼かない**
  —— 「git に入る plan.json に機械依存の値を焼かない」がそのまま効く

### 2. 読ませる画面

- **1 ビート = 全文。** `say` を段落で、`do` を手順で、**折らない・切らない**。
  撮る画面が列を切り詰めているのは編集欄と一覧を同居させているからで、
  読むだけならその制約が無い
- **台本を撮ったときのショットを参考画像として同梱できる**（あれば出す、無ければ
  進む）。動画を配るのとは別 —— 1 枚ずつ、その手順の絵として出す

### 3. 進み方

- ボタンは「出来た」「分からない」の 2 つで足りる
- **出来たかどうかは機械には分からない。** UI Automation が届かない相手だから
  支援収録になっている。**確認したふりをしない**（チェックが付いたことは
  「押した」以上の意味を持たない）
- 「分からない」で**その場を撮って**質問に添えられる。撮る部品はもうある

### 4. 束ねて配る

台本 + 仕込みスクリプト + 参考画像を 1 つに。**mp4 は要らない** —— 動画は
[Gallery](https://lancard-aikawa.github.io/GhostMoviePlayGallery/)、教材は実アプリ。

**ここは [AI に操作させる案](desktop.md#人の代わりを-ai-にやらせる駆動の当て)と
共通の部品**なので、別に書いた（[手順を束ねて配る](bundle.md)）。
**落とした束は相手の機械でコマンドを走らせる**ので、運ぶ前に「見せる」が要る。

## 芯にあるものとの関係

| | |
| --- | --- |
| AI の仕事は演目の設計 | **そのまま。** 教材の中身は Pass1 が書く |
| `plan.json` は人が直せる中間表現 | **そのまま。同じ台本から動画と教材が出る** |
| リプレイが決定論的 | **ここだけ効かない。** 操作するのが人なので |

## 引っかかるところ

1. **`do` に撮り方が混ざっている。** いまは `※ 録画で撮る`「まず `起動` を押す」を
   `do` に書いている（Krita の 1 本で実際に書いた）。教材で読ませるとノイズになる。
   **撮り方をビートの別の欄に分ける**か、教材側で落とすか。
   —— 「絵を決めるものを `plan.EDITABLE` に入れない」と同じ判断を、もう一度することになる
2. **腐る。しかも動画より悪い。** `gmp check` は支援収録を検査できない（撮り直せない
   から）。動画なら「古い」で済むが、**教材は相手の機械で嘘の手順を踏ませる**。
   配る前に誰かが通しでやる以外に手が無い —— **ここが最大の未解決**
3. **宛先。** 手順書レンダラを下げたときと同じ問いが立つ。ただし**これは出力物では
   なく道具**で、**動画では代われない**（相手が自分のデータで手を動かす）ぶんだけ
   立場が違う

## 見立て

**最初の一歩は「別アプリを作る」ではない。** 台本を読んで 1 ビートを全文で出す
だけの窓（100 行ほど）で、**Krita の 1 本を人に通してもらう**。そこで分かるのは
1 つだけで、それがいちばん大事:

> **`do` は、撮る人ではなく教わる人に通じるか。**

通じるなら、あとは既にある部品の組み替えになる。通じないなら、直すのは画面では
なく Pass1 の書かせ方（依頼文と SKILL.md）で、それは**動画の側にも効く**。

インストール・パス確定・配布は、その後でいい。**先に作ると、通じない `do` を
配る仕組みだけが出来上がる。**

## 人にやらせるのがいちばん高い

念のため —— **この案は「教えること」自体が目的のときだけ引き合う。**
動画を作るために人を動かすなら、[`do` を AI に読ませて 1 回だけ操作させ、
`actions` に起こす](desktop.md#人の代わりを-ai-にやらせる駆動の当て)ほうが安い。
撮り直しが無料に戻るぶん、桁で違う。

**`do` が両方の入口になっている**のは同じで、宛先が人か AI かだけが違う。
